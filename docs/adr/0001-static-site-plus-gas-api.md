# 画面はGitHub Pagesに置き、GASはスプレッドシートの読み書きだけに使う

選手DBとフォーメーションはGoogleスプレッドシートに置く。アプリ全体をGAS Webアプリにすれば、スプレッドシートと同じ場所で完結する。それでも画面はGitHub Pagesの静的サイトに分けた。GASの画面は制限付きのiframe内で動くため、iPhoneでの画像保存(共有シート経由の「写真に保存」)やタッチでのドラッグに不具合が出やすいからだ。GASは読み書き用のAPIとしてだけ使う。

## Consequences

- アプリのコードは公開リポジトリに置かれる。選手データとフォーメーションはスプレッドシート側にあり、公開されない。
- GAS APIのURLを知っていれば誰でもフォーメーションを書き換えられる。利用者は本人だけで、URLを知られなければよいという前提で、これを許容している。
- そのため、GAS APIのURLはコードに書かない。公開リポジトリに書くと誰でも読めてしまうからだ。URLは端末ごとに「接続設定」で入力し、そのブラウザにだけ保存する。iPhoneへは、URLを埋め込んだリンク(`index.html#api=…`)を開いて渡せる。
- GASはCORSの事前確認に応えないため、POSTは `Content-Type: text/plain` でJSONを送る。
